# PRD 审核

导入的初版 PRD 往往存在各种问题【已确认】，因此开发前设置"AI 预审 + 人工审核"两道关。

## 1. AI 预审

### 输入
- 当前 PRD 版本全文（Markdown，含图片说明文字）
- 绑定项目的上下文卡片（技术栈、目录结构）
- 【建议】允许预审 Agent **只读**访问项目代码，以发现"与现有实现冲突"的问题（如字段已存在、接口重名）

### 执行方式
- 默认使用 Claude Code / Codex 的只读模式（Claude Code：`--permission-mode plan` 或仅允许 Read/Grep/Glob 工具；Codex：`--sandbox read-only`），在项目主目录运行，不创建 worktree。
- 也可配置为直接调用 Provider 的 Chat API（不需要读代码时更快、更便宜）。
- 要求 Agent 输出严格的 JSON（见下），系统解析后入库；解析失败则保留原文并提示重试。

### 检查维度（Checklist）

| 类别 | 检查点 |
| --- | --- |
| 完整性 | 背景/目标、用户角色、功能点、验收标准是否齐全 |
| 歧义 | 模糊词（"适当""尽快""类似 xx"）、未定义名词 |
| 数据 | 字段名、类型、长度、必填、默认值、枚举值是否定义 |
| 流程 | 异常流程、边界条件、空状态、并发、幂等 |
| 接口 | 前后端交互点是否明确，是否需要新接口/修改旧接口 |
| 权限与安全 | 谁能操作、越权、敏感数据 |
| 非功能 | 性能、分页、兼容性、国际化 |
| 一致性 | PRD 内部前后矛盾；与现有代码/已有功能冲突 |
| 可测试性 | 验收标准是否可验证 |
| 拆分 | 是否涉及前端 / 后端 / 两者，建议的拆分方式 |

### 输出格式

```json
{
  "summary": "一句话评价 PRD 质量",
  "scope": { "backend": true, "frontend": true },
  "issues": [
    {
      "id": "I-1",
      "severity": "blocker | major | minor | suggestion",
      "category": "data | flow | ambiguity | ...",
      "location": "PRD 中引用的原文片段或章节",
      "problem": "问题描述",
      "question": "需要向需求方确认的问题（可选）",
      "suggestion": "建议的修改文本（可直接采纳）"
    }
  ],
  "acceptance_criteria_draft": ["可验证的验收标准 1", "..."]
}
```

## 2. 人工审核

审核页左右分栏：左侧 PRD 编辑器（当前版本），右侧问题清单。

每个问题的操作：

| 操作 | 效果 |
| --- | --- |
| **采纳建议** | 把 `suggestion` 应用到 PRD（AI 生成补丁，用户预览后确认），产生新版本 |
| **手动修改** | 用户自行编辑，标记问题为已解决 |
| **忽略** | 需填写理由（如"本期不做"），理由会写入 PRD 的"备注 / 不做范围" |
| **待确认** | 需要问需求方；可一键把所有"待确认"问题导出为一段可发给需求方的文字 |

其他能力：
- **重新预审**：修改后可再跑一次，只关注变化部分和未关闭问题。
- **版本对比**：任意两版并排 Diff，标注每版的来源（导入 / AI 采纳 / 手动）。
- **验收标准编辑**：从 AI 草稿中勾选、修改，定稿前必须非空。
- 【建议】**澄清记录**：把需求方的口头答复记录为"澄清"，自动并入 PRD 的"澄清说明"章节，保证 Agent 能看到。

## 3. 定稿与拆分

1. 点击"定稿"，校验无未处理的 `blocker`。
2. AI 根据定稿 PRD + 项目信息生成**拆分建议**：
   - BE 子任务：数据模型、接口、业务逻辑、单测；**第一步产出 API 文档**。
   - FE 子任务：页面、组件、状态管理、接口对接（依赖 API 文档）。
   - 每个子任务带：标题、需求摘录、验收标准、建议 Agent。
3. 用户确认 / 调整子任务（合并、拆开、改项目、改 Agent），然后锁定。
4. 系统为每个子任务创建分支 `tw/<ticket-key>-<kind>`（如 `tw/TW-42-be`）和 worktree。

## 4. PRD 标准结构【建议】

导入后的 PRD 会被（可选地）AI 规整为以下结构，便于预审和后续拆分：

```markdown
# <标题>
## 背景与目标
## 用户与场景
## 功能需求
### F1 ...
## 数据定义
## 接口与交互（前后端约定）
## 异常与边界
## 非功能需求
## 验收标准
## 不做范围
## 澄清说明
```

规整操作产生新版本（作者 `ai`），原文保留在 v1，可随时对比。
