# Prompt 与上下文组装

Agent 的效果很大程度取决于给它的上下文。观澜负责把散落的信息自动拼成高质量的任务说明，免去每次手动解释。

## 1. 上下文来源

| 层级 | 内容 | 维护方式 |
| --- | --- | --- |
| 全局 | 用户的个人编码偏好（语言、注释风格、提交规范） | 设置页 |
| 项目 | 上下文卡片：技术栈、目录结构说明、规范、命令、注意事项 | 项目页；可从 `CLAUDE.md` / `AGENTS.md` 导入 |
| 工单 | 定稿 PRD（或其与本子任务相关的摘录）、验收标准、澄清说明 | 工作流自动 |
| 子任务 | 任务范围、依赖产物（如 API 文档）、产出要求 | 拆分时生成 |
| 本轮 | 打回意见、行内评论、测试失败输出、变更影响分析 | 自动 |

> Claude Code 会自动读取仓库中的 `CLAUDE.md`，Codex 会读取 `AGENTS.md`。观澜**不改写**这些文件，项目卡片中的内容通过 Prompt 传入；如用户愿意，可提供"同步到 AGENTS.md / CLAUDE.md"的选项。

## 2. 模板

模板使用 Markdown + 变量（如 `{{ticket.title}}`），按用途区分，可在设置中自定义：

| 模板 | 用途 |
| --- | --- |
| `prd_review` | AI 预审（输出 JSON 问题清单） |
| `prd_normalize` | PRD 规整为标准结构 |
| `task_split` | 定稿后拆分子任务 |
| `backend_dev` | 后端开发：**先写 API 文档**再实现 |
| `frontend_dev` | 前端开发：依据 API 文档对接 |
| `bug_fix` | Bug 修复：先复现（可选写失败测试）再修复 |
| `rework` | 打回返工 |
| `test_fix` | 测试失败自动修复 |
| `change_impact` | 变更影响分析 |
| `code_review` | AI 交叉审查 |

### 示例：`backend_dev`

```markdown
你是本项目的后端开发者。请在当前目录（一个独立的 git worktree）中完成以下任务。

## 项目背景
{{project.context}}

## 需求（已定稿，版本 v{{ticket.finalized_version}}）
{{task.spec}}

## 验收标准
{{task.acceptance_criteria}}

## 工作要求
1. 第一步：在 `docs/api/{{ticket.key}}.md` 写出本需求涉及的全部接口文档
   （路径、方法、请求/响应结构、字段说明、错误码、示例），完成后单独提交一次，
   提交信息为 `docs(api): {{ticket.key}}`。
2. 然后实现功能，并补充必要的单元测试。
3. 运行 `{{project.commands.test}}` 确保通过。
4. 不要修改与本任务无关的文件；不要推送到远程。
5. 最后用简短中文总结：做了什么、改了哪些文件、有哪些未完成或需要人工确认的点。
```

## 3. 上下文预算

- PRD 过长时只传与子任务相关的摘录（拆分阶段已生成），全文以文件形式放在 worktree 外的临时目录，并在 Prompt 中告知路径供按需读取。
- 附件图片：对支持图片的 Agent 以文件路径提供；否则提供 AI 生成的文字描述。
- 返工轮次优先 resume 原会话，只传增量信息。

## 4. 预览与编辑

每次运行前可"预览 Prompt"，允许临时修改后再启动；实际发送的 Prompt 完整保存在 Run 记录中，便于复盘和改进模板。
