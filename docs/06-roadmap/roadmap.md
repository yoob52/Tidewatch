# 路线图

> 估时按"一人业余 / 借助 Agent 开发"粗估，仅供排期参考。

## M0 · 技术验证（约 1 周）
- [x] Tauri 2 空壳 + React + SQLite 跑通
- [ ] Windows 下 spawn `claude -p --output-format stream-json` 并实时解析，Job Object 停止进程树（Linux 上用真实 Claude Code 跑通改动 / 停止 / 续接；Windows 上 Job Object 与演示 Agent 由 CI 验证，真实 Claude Code 还没在 Windows 上跑过）
- [x] spawn `codex exec --json`，解析事件与 session id，验证 `resume`（Linux，经自定义 Provider）
- [ ] 通过环境变量让 Claude Code 使用 DeepSeek Anthropic 兼容端点（同一套注入已用另一个 Anthropic 兼容中转站跑通；DeepSeek 本身还没有 Key 实测）
- [x] git worktree 创建 / 删除，长路径验证
- [ ] 【建议】`CLAUDE_CONFIG_DIR` / `CODEX_HOME` 多实例隔离与登录；录制两种 Agent 的真实会话作为回放测试样本（见 [Agent 管理](../03-agent/agent-management.md)）

**验收**：命令行级 Demo 能在一个 worktree 中让两种 Agent 各完成一个小改动并可中途停止。

## M1 · MVP：手动工单 + Agent 执行（约 2–3 周）
- [x] 项目管理（本地目录、上下文卡片、命令）
- [x] 工单创建（表单 / 粘贴 / md 导入）、看板
- [x] Provider 配置（含凭据管理器）与按进程注入
- [x] 子任务手动创建 → worktree → 运行 → 实时日志 → 停止 / 恢复
- [x] 自动提交、自动测试、Diff 视图、合并、清理
- [ ] 成本与耗时统计、Windows 通知（统计已完成；通知已接入，还没在 Windows 上实际弹出过）
- [ ] 【建议】Agent 实例与能力声明、Run / Attempt、完成屏障（"收尾中"）、命令落盘与孤儿恢复、检查点 ref（Agent 实例与能力声明还没做，其余已完成）

**验收**：可以把一个 Bug 工单从创建跑到合并。

**M1 结果**：执行引擎用演示 Agent 的端到端测试走通了"建 Bug 工单 → 子任务 → 运行 → 停止 → 续接 → 检查 → 验收 → 合并 → 清理"，以及排队、幂等、失败、打回返工和孤儿恢复（Linux 与 Windows CI）。桌面界面的各页面在 Linux 上用真实数据打开看过；**界面上的操作（点击建单、开始、验收、合并）还没有逐项点过**，真实的 Claude Code / Codex 也还没有经桌面应用跑过（M0 只在命令行里验证）。这一版没有 AI 预审和 AI 拆分：「AI 预审」一列需要手动点「预审完成」，子任务要手动创建，这些在 M2。

## M2 · 工作流与 PRD 审核（约 2–3 周）
- [x] 完整状态机与 Bug 快速通道
- [x] PRD 版本与对比
- [x] AI 预审 → 问题清单 → 采纳 / 忽略 / 待确认
- [x] 定稿锁定 + AI 拆分 FE/BE 子任务 + 依赖（API 文档产物解锁前端）
- [x] 验收打回（行内评论 → 返工 Run，优先 resume）
- [x] 定稿后变更流程与影响分析
- [x] Prompt 模板可编辑与预览
- [x] 【建议】换 Agent / resume 失败时的显式上下文交接
- [ ] 【建议】追加指令的分发方式（原地引导 / 中断后重启 / 排队）——现在只有"停止后续接 + 新指令"一种，其余依赖 M3 的交互通道

**验收**：一个前后端混合 PRD 走完 草稿 → 预审 → 定稿 → BE 先出 API 文档 → FE 跟进 → 验收打回一次 → 完成。

**M2 结果**：上面这条验收路径有端到端测试（演示 Agent，Linux 与 Windows CI）：混合 PRD 预审出问题清单 → 阻塞问题未处理时不能定稿 → 采纳后定稿 → AI 拆分出后端 / 前端 → 后端写出接口文档即解锁前端 → 验收打回一次并返工 → 合并完成；另有定稿后变更与影响分析、预审失败保留原始输出并可重试、换 Agent 时的上下文交接。桌面界面上，审核页（采纳建议）、拆分建议确认、影响分析和 Prompt 模板编辑在 Linux 上用演示数据打开并点过；**整条流程还没有在桌面窗口里从头到尾点一遍**，真实的 Claude Code / Codex 也没有跑过预审和拆分（它们能否稳定按要求输出 JSON 尚未验证）。

## M3 · V1 完善（约 2–3 周）
- [x] docx / pdf 导入、图片附件与描述；权威图 / 参考图标记并随预审、开发发给 Agent（见 [PRD 中的图片](../02-workflow/prd-images.md)）——图片描述由人填写，还不会让 AI 自动生成；过大的图还不会另存压缩副本
- [x] 智能创建（自动识别类型 / 项目）——用本机规则识别类型、项目、优先级、标签和 Bug 三要素并列出依据，用户确认后才建单；没有调用 AI 做分析
- [x] AI 交叉 Review、测试失败自动修复
- [x] 预算护栏、卡住检测、危险命令高亮
- [x] 推送分支与 `gh pr create`——只在用户点按钮时执行，观澜自己从不推送
- [ ] 统计仪表盘、备份导出、自动更新（统计和备份导出已完成；更新只做到"检查有没有新版本并给出下载页"，不会自动下载和安装）
- [x] LiteLLM 桥接引导
- [ ] 【建议】交互通道（`codex app-server` 等）：逐项审批、结构化提问、`supervised` 档位、运行中引导、会话回滚

**M3 结果**：每一项都有核心层的单元测试或端到端测试（演示 Agent）：导入解析与图片去重 / 效力标记、护栏触发后停止运行、检查失败后自动修复直到通过或次数用完、交叉审查只读且不改变子任务状态、推送与开 PR 只在调用时发生（本地裸仓库作远端）、备份保留 7 份与导出归档、每周统计、桥接配置里不含密钥、版本比较与无发布 / 服务器出错的处理。**没有验证的**：真实 Claude Code 带图片跑一次（中转站额度用完时返回 429）、`gh pr create` 对真实 GitHub 仓库开 PR（测试里用假的 `gh`，且只在 Linux 上跑）、检查更新对真实发布页（仓库还没有发布过版本）、Windows 上的结果以 CI 为准。交互通道没有做。

## M4 · V2 探索
- [x] GitHub Issues 同步（真实仓库只验证了只读拉取；写回评论 / 关闭只对假服务测过）
- [ ] 飞书同步：只做了按链接导入云文档（`/docx/`、`/wiki/`），**未对真实飞书验证**；飞书项目、多维表格没有做
- [x] 更多 Agent：OpenCode、Aider（真实跑通，OpenAI 兼容端点）
- [ ] 更多 Agent：Gemini CLI 的成功路径未用真实账号验证
- [x] 多 Agent 同题对比（只用演示 Agent 测过）
- [x] 本地 HTTP / MCP 接口，含 Agent 委派工具（真实 Codex、OpenCode、Claude Code 经 MCP 跑通）
- [x] 自定义工作流：在内置状态上加自定义环节。功能清单里的「自定义状态与转换」没有做，见 [工作流 §7](../02-workflow/workflow.md)
- [x] 轻量协作（成员与角色、令牌、指派、时间线记名、远程访问开关、只读看板页面）。远程访问没有跨机器验证

**M4 结果**：各项都有核心层的单元测试或端到端测试（演示 Agent、本地假服务）：GitHub / 飞书同步的新建、去重、「源已变更」的应用与忽略、写回；三个新适配器的输出解析；令牌与角色、REST、MCP 工具、Agent 经 MCP 提问与委派；自定义环节卡定稿与完成、退回后重置、自动完成；对比的候选各自的 worktree、采用后其余取消并改依赖。接口说明见 [本地接口与轻量协作](../04-architecture/local-api.md)。**没有验证的**：上面各项括号里写明的，以及 M4 的新界面没有在桌面窗口里逐项点过；Windows 上的结果以 CI 为准。
