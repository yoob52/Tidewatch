# 观澜 Tidewatch · 界面原型 v2

从零重新设计的中文可点击原型，用来在正式开发前确认视觉方向与主要流程。未参考 `prototype/` 第一版。

纯静态页面：没有后端、没有依赖、不发任何网络请求；所有工单、运行、费用、测试结果都是写在 `js/data.js` 里的演示数据。

## 打开方式

直接双击 `index.html`，或：

```bash
python3 -m http.server 4173 --directory prototype-v2
```

## 设计方向

- **纸与墨**：宣纸底色、墨色文字，标题用宋体，正文用黑体，编号 / 路径 / 命令用等宽字体。
- **两种颜色各管一件事**：黛青表示「Agent 在做」，朱砂只用在「等你处理」的地方（人工审核、验收、阻塞问题）。
- **潮位计**：侧栏底部的水位表示运行队列的并发占用，点击进入运行面板。
- **一字印**：后 / 前 / 混 / 虫 / 杂 五种工单类型用小方印区分。
- 亮色与暗色两套主题，右上角切换。

## 可以点的流程

- **看板拖拽**：按 `docs/02-workflow/workflow.md` 的状态机校验，不合法的流转会说明原因；Bug 可从「草稿」直接拖到「开发中」。
- **PRD 审核（TW-42）**：采纳 / 手动修改 / 待确认 / 忽略（需填理由）；两个阻塞问题处理完后「定稿」才可点；定稿弹窗展示 AI 拆分建议，确认后工单进入开发。
- **验收（TW-39）**：并排 Diff、行内评论、勾选验收标准、通过或打回。
- **运行面板（R-121）**：日志逐条流入，计时与 Token 实时增长，跑完后子任务变为待验收；可停止、追加指令。
- **新建工单**：粘贴示例 → 智能识别为 Bug 并拆出复现步骤 → 保存后出现在看板。
- **其他**：`Ctrl+K` 命令面板、通知抽屉、Provider 测试连接、设置里的开关与并发上限。

标了「演示：…」提示的按钮只是布局示意，没有实际行为。完整数据只为 TW-42（审核中）和 TW-39（开发 / 验收中）准备，其他工单的详情页显示空状态。
